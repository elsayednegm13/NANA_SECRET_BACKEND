# NANA SECRET — فصل الباك إند عن الفرونت إند

المشروع أصبح تطبيقين مستقلين، بدون تغيير التصميم أو التحويل إلى React أو إطار عمل جديد:

- `frontend/`: صفحات HTML وCSS وJavaScript، بما فيها لوحة التحكم.
- `backend/`: Express API، قاعدة SQLite، الصور المرفوعة وإرسال رسائل التواصل عبر Resend.
- التواصل بينهما عبر HTTP وBearer token كما كان، مع إعداد مركزي لعنوان الـAPI.

التفاصيل الفنية والملاحظات الأمنية: [تقرير تحليل المشروع](docs/PROJECT-ANALYSIS.md).

## 1. التشغيل المحلي

المتطلبات: Node.js إصدار 22 أو أحدث وnpm. من المجلد الرئيسي:

```sh
npm run setup
npm run dev
```

الأمر الأول يثبت اعتماديات التطبيقين باستخدام ملف القفل الخاص بكل تطبيق. `npm install` في الجذر وحده لا يثبت اعتماديات التطبيقين.

افتح:

- الموقع: `http://localhost:3000`
- تسجيل الدخول: `http://localhost:3000/login.html`
- لوحة التحكم: `http://localhost:3000/admin.html`
- فحص تشغيل API: `http://localhost:4000/api/health`

لا تفتح HTML مباشرة باستخدام `file://`؛ لوحة التحكم تحتاج أيضًا إلى جلب صفحات الموقع عبر HTTP لقراءة عناصر محرر المحتوى.

`Ctrl+C` يوقف التطبيقين في وضع التطوير. لتشغيل كل تطبيق منفصلًا، افتح نافذتين:

```sh
npm run backend
```

```sh
npm run frontend
```

يمكن أيضًا الدخول إلى `backend` أو `frontend` وتشغيل `npm ci` ثم `npm start`، بدون الحاجة إلى التطبيق الآخر على نفس الجهاز. أمر `npm start` من جذر المشروع يشغل الباك إند فقط، وليس الموقع.

## 2. الإعدادات

انسخ `backend/.env.example` إلى `backend/.env` إذا أردت تغيير الإعدادات. في PowerShell من جذر المشروع:

```powershell
Copy-Item backend/.env.example backend/.env
```

وفي Git Bash:

```sh
cp backend/.env.example backend/.env
```

الإعدادات الأساسية:

| المتغير | الوظيفة | الافتراضي |
| --- | --- | --- |
| `PORT` | منفذ الباك إند | `4000` |
| `FRONTEND_ORIGINS` | عناوين الواجهة المسموح لها باستخدام API | `http://localhost:3000,http://127.0.0.1:3000` |
| `ADMIN_USER` | اسم المدير الرئيسي، ويُنشأ إذا لم يكن موجودًا | `ADMIN` |
| `ADMIN_PASS` | كلمة مرور إنشاء المدير، وليست إعادة تعيين لحساب موجود | `123` |
| `SESSION_SECRET` | السر المستخدم في نظام كلمات المرور والجلسات الحالي | `local-secret` للتطوير فقط |
| `DATA_DIR` | مجلد قاعدة البيانات | `data` داخل الباك إند |
| `UPLOADS_DIR` | مجلد الصور المرفوعة | `uploads` داخل الباك إند |
| `RESEND_API_KEY` | مفتاح خدمة البريد | فارغ |
| `CONTACT_TO` | البريد الذي يستقبل الرسائل | البريد الحالي في ملف المثال |
| `RESEND_FROM` | عنوان مرسل البريد | عنوان Resend التجريبي |

المسارات النسبية محسوبة من `backend/` وليس مكان تنفيذ الأمر. ملف `.env` يُقرأ من `backend/`، ومتغيرات بيئة الاستضافة لها الأولوية.

منفذ سيرفر الواجهة الاختياري يُحدد بمتغير `FRONTEND_PORT`، وافتراضيه `3000`. عيّنه في بيئة عملية الفرونت إند، وليس في `backend/.env`. عند تغيير المنفذ، عدّل `FRONTEND_ORIGINS` بما يطابق عنوان الواجهة الجديد، ثم أعد تشغيل الباك إند.

### عنوان الـAPI في الواجهة

الإعداد موجود في `frontend/assets/js/config.js`. القيمة المحلية:

```js
window.NANA_API_BASE = "http://localhost:4000";
```

عند النشر غيّر القيمة الافتراضية في نفس الملف إلى عنوان API الحقيقي، مثل:

```js
window.NANA_API_BASE = "https://api.example.com";
```

يمكن أيضًا تعريف `window.NANA_API_BASE` في الصفحة قبل تحميل `config.js`. المتغير ليس متغير `.env`؛ الواجهة ملفات ثابتة ولا تحتوي خطوة بناء أو حقن متغيرات تلقائية.

إذا استخدمت reverse proxy على نفس دومين الموقع، اجعل القيمة `""` واضبط الوكيل لتمرير `/api` و`/uploads` إلى الباك إند، وباقي الطلبات إلى الفرونت إند.

الصور الثابتة `assets/images/...` تُحمّل من الفرونت إند. الصور المرفوعة `/uploads/...` و`uploads/...` تُحمّل من الباك إند تلقائيًا في الصفحات ولوحة التحكم. لا حاجة لتعديل الروابط المحفوظة في قاعدة البيانات.

## 3. البيانات الحالية والحسابات

تم نقل الملفات الحالية، وليس إنشاء نسخة بديلة منها:

- `data/nana-secret.sqlite` ← أصبح `backend/data/nana-secret.sqlite`.
- `data/products-seed.json` ← أصبح `backend/data/products-seed.json`.
- `uploads/` ← أصبح `backend/uploads/`.

خذ نسخة احتياطية من قاعدة البيانات والصور قبل النشر. لا تحذف قاعدة البيانات لمحاولة إصلاح تسجيل الدخول.

**مهم جدًا مع قاعدة البيانات الحالية:**

- حافظ على قيمة `SESSION_SECRET` المستخدمة قبل الفصل. النظام القديم يدخل هذا السر في تجزئة كلمات المرور؛ تغييره يجعل كلمات المرور المحفوظة غير صالحة.
- لو لم يكن هناك سر مخصص سابقًا، القيمة القديمة كانت `local-secret`. تحسين النظام وتدوير السر يحتاجان خطة ترحيل لكلمات المرور؛ لم ننفذ ترحيلًا ضمن الفصل.
- تغيير `ADMIN_PASS` في البيئة لا يغير كلمة مرور مدير موجود. غيّر كلمة المرور من إدارة المستخدمين وأنت مسجل الدخول، أو نفّذ إجراء استعادة مُراجع إذا كان الحساب غير متاح.
- بيانات `ADMIN` / `123` هي افتراضيات الإنشاء للتطوير فقط؛ ليس ضمانًا أنها بيانات الحساب الموجود حاليًا.
- لم نغير خوارزمية كلمات المرور أو نماذج البيانات أثناء الفصل.

تم الحفاظ على ملفات البيانات والصور الموجودة في المشروع. لا تضف بيانات إنتاج أو نسخًا احتياطية حساسة إلى Git. ملف `.gitignore` يمنع ملفات البيئة والاعتماديات وملفات SQLite المؤقتة؛ تنظيف تاريخ البيانات القديمة من Git مهمة منفصلة.

## 4. النشر المستقل

### الباك إند

1. انشر مجلد `backend/` كتطبيق Node.js.
2. أمر التثبيت: `npm ci`، وأمر التشغيل: `npm start`.
3. اضبط متغيرات البيئة في الاستضافة.
4. اضبط `FRONTEND_ORIGINS` كقائمة origins كاملة، مفصولة بفواصل وبدون `/` في النهاية، مثال: `https://www.example.com,https://example.com`.
5. استخدم تخزينًا دائمًا لقاعدة البيانات والصور، وحدد `DATA_DIR` و`UPLOADS_DIR` عند الحاجة.
6. استخدم HTTPS؛ لا تتصل من موقع HTTPS بباك إند HTTP.

CORS ليس نظام صلاحيات: طلبات الأدوات والسيرفرات بدون `Origin` مسموحة، والكتابة ما زالت تتطلب Bearer token. الجلسات في ذاكرة العملية وتختفي عند إعادة تشغيل السيرفر. SQLite والجلسات الحالية مناسبة لعملية سيرفر واحدة؛ التوسع لعدة نسخ يحتاج تصميمًا إضافيًا.

### الفرونت إند

1. اضبط عنوان API في `assets/js/config.js`.
2. انشر ملفات HTML ومجلد `assets/` على استضافة ثابتة؛ لا يوجد build مطلوب.
3. لا ترفع `backend/` أو قاعدة البيانات أو `.env` أو ملفات Node إلى المجلد العام.
4. إذا كنت تستخدم سيرفر Node المرفق بدل الاستضافة الثابتة، شغل `npm ci` ثم `npm start` داخل `frontend/` واضبط `FRONTEND_PORT` حسب الاستضافة.

إعدادات الواجهة عامة. مفاتيح Resend وكلمات المرور والأسرار تبقى على الباك إند فقط. اقرأ [إعداد البريد](README-RESEND.md) لتفعيل نموذج التواصل.

## 5. الاختبارات ونتيجة الفحص

من الجذر:

```sh
npm test
npm audit --prefix backend --omit=dev
npm audit --prefix frontend --omit=dev
```

اختبارات الباك إند تستخدم قاعدة بيانات ومجلد صور مؤقتين، ولا تفتح قاعدة المشروع الأصلية. تشمل API والمصادقة وCORS وحجب الملفات الخاصة ورفع الصور. اختبارات الواجهة تشمل الروابط والصور ونموذج التواصل وربط لوحة التحكم باستخدام محاكاة DOM؛ ليست بديلًا لاختبار المتصفح الكامل.

لم يتم اختبار إرسال بريد حقيقي أو النشر على استضافة خارجية. فحص الاعتماديات أثناء الفصل أظهر 12 تنبيهًا في الباك إند: 2 حرجة، و7 عالية، و1 متوسطة، و2 منخفضة. الواجهة: لا تنبيهات في الفحص الحالي. لم تُجرَ ترقيات كبيرة أو `npm audit fix --force` حتى لا تتغير المكتبات وسلوك المشروع خارج نطاق الفصل. راجع التقرير وعالجها قبل الإنتاج.
